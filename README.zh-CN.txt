Modern Remote 原型运行说明

这是一个 SwiftUI 双端原型：iPhone 浏览音乐资料库，Mac 上的系统“音乐”应用实际播放。没有自建服务器和账号系统，也不收集 Apple ID 密码。

一、打开和运行

1. 用 Xcode 16 或更新版本打开 ModernRemote.xcodeproj。
2. 为 ModernRemoteMac 和 ModernRemoteiOS 两个目标选择自己的开发团队，替换示例 Bundle Identifier。
3. 在 Apple 开发者后台为 iOS 应用标识启用 MusicKit 服务，并更新签名配置。需要支持该服务的开发团队和描述文件。
4. 先运行 Mac 目标。确认系统“音乐”应用已登录所需账号，而且能够正常播放歌曲。
5. 点击 开启共享，允许自动化控制“音乐”，按提示允许本地网络访问。
6. 用 Xcode 把 iOS 目标安装到真实 iPhone。最低要求为 iOS 17，Mac 最低要求为 macOS 14。
7. 两台设备接入同一局域网。在 iPhone 的 连接 页面选择 Mac，粘贴 Mac 窗口显示的 四位数字配对码。
8. 在 资料库页面点击 允许访问 Apple Music，通过系统授权浏览资料库。不需要在本软件内登录 Apple ID。
9. 点击歌曲，在 Mac 播放。正在播放 页面可播放、暂停、切歌、调整进度和“音乐”应用音量。
10. 点击 Mac 上的 停止共享 会断开连接并更换配对码。重新共享后，需要用新配对码配对。

只编译 Mac 端时，可以运行 Scripts/build-mac.sh，然后打开生成的 .build/ModernRemoteMac.app。这条路径只需要命令行开发工具；生成的应用为本机临时签名，未公证，不是可直接对外分发的正式安装包。

二、资料库和播放限制

原对话关于原生 macOS 可通过 SystemMusicPlayer 直接控制系统“音乐”的说法需要纠正。Apple 当前文档没有列出原生 macOS 支持。这个原型改用“音乐”应用的 AppleScript 接口，仍然由系统“音乐”应用负责播放。

iPhone 使用 MusicKit 加载歌曲和播放列表，并按歌曲元数据组织专辑与艺人。合辑可能按不同歌曲艺人拆分。搜索只覆盖已经加载的资料库，不搜索整个 Apple Music 在线曲库。播放列表支持分页读取，暂不显示音乐视频，也不能编辑播放列表或一键替换整张专辑的队列。

iPhone 资料库 ID 不是 Mac 的曲目 ID。原型按曲名、艺人、专辑和时长寻找唯一匹配。没有匹配或存在多个版本时，会显示错误，不会随便选择一首。可以先在 Mac 加入或同步该歌曲，也可以直接从 Mac 资料库 选择。

未同步的 Mac 本地歌曲通过 Mac 资料库 读取，每页最多 200 首，并用 Mac 的持久 ID 播放。该入口的搜索仅覆盖已加载页面，目前不展示 Mac 独有的播放列表。

完整 Up Next 队列没有公开可靠的读取与编辑实现，因此本原型不展示或编辑完整队列。上一首、下一首沿用系统“音乐”当前播放上下文，点击歌曲不代表整个专辑或播放列表都会加入队列。

Mac 必须保持运行和唤醒。iPhone 进入后台或更换网络后可能需要手动重连。状态每两秒刷新一次。进度拖动或连续操作时，最多保留一个后续指令，最新操作优先。云端歌曲仍要求 Mac 自身具有播放权限及必要的网络连接。

三、安全与权限

通信使用 Network.framework、Bonjour 和带预共享配对码的 TLS 加密。配对码不会以普通消息发送，也不会保存到磁盘。停止共享后旧配对码失效。每次只允许一个控制端连接。

本原型面向个人局域网，并非经过全面安全审计的多用户服务。Mac 端没有启用应用沙盒，但启用了 Hardened Runtime 和 Apple Events 权限。上架应用商店前需要重新评估沙盒与分发要求。

项目已经包含 Info.plist、本地网络说明、Bonjour 服务声明、Apple Music 使用说明以及必要的权限配置。不含后台音频权限。

四、已验证和未验证

已经通过：Mac 源码类型检查和可执行文件编译；iOS 源码在本机 Mac SDK 下的交叉检查；iOS 数据与通信代码的 Mac Catalyst 类型检查；实际 AppleScript 脚本语法编译；消息拆包、合包、长度和版本检查；真实回环 TLS 加密通信及错误配对码拒绝测试；Xcode 项目与权限配置结构检查。

使用 Xcode 26.3 已通过 Mac Release、iOS 真机 SDK Release 和模拟器编译。模拟器曾成功发现真实 Mac 并完成加密配对；四位配对码版本另外通过了实际回环通信、错误码拒绝、前导零、换码和错误次数限制测试。

GitHub 发布包包含 Mac 应用 ZIP 与未签名的 iOS IPA。iOS IPA 需要用自己的证书和描述文件重新签名后安装。MusicKit 授权还取决于应用标识及描述文件是否支持该服务，单纯自签不保证获得 MusicKit 权限。也可使用 Mac 资料库入口。

尚未完成真实 iPhone 安装、MusicKit 账号授权、实际选歌播放及大型曲库的完整联调。Mac 应用采用临时签名，未公证。发布内容不包含证书、私钥、真实配对码和个人曲库。

用 Scripts/test.sh 可重跑通信与协议测试。英文 README.md 包含完整目录说明、排错方法、验收清单和 Apple 官方资料链接。

五、常见问题

找不到 Mac：确认已开始共享、接入同一子网、允许本地网络与防火墙连接，且路由器未启用访客隔离。

拒绝自动化或错误 -1743：在 Mac 系统设置的“隐私与安全性—自动化”中允许本应用控制“音乐”。

资料库授权被拒绝：在 iPhone 设置中检查“媒体与 Apple Music”权限，再重新加载。

签名失败：检查开发团队、应用标识、MusicKit 服务和描述文件。不要把账号密码或开发者私钥写进代码。

本说明使用 GBK 严格编码并经过回读校验。Swift 源码及 Xcode 配置按开发工具要求使用 UTF-8。

四位配对码更新

Mac 端显示四位随机数字，保留前导零，例如 0386。iPhone 使用数字键盘，输入框最多保留四位数字。停止共享后会换成不同的配对码。一分钟内出现五次失败握手后，将暂停接受配对一分钟。

连接仍使用 TLS 加密。四位配对码只有一万种组合，错误次数限制只能限制在线尝试，无法防止针对捕获握手数据的离线猜测；此便利模式按可信个人局域网设计。
